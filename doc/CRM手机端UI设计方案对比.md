## 一、简报（Brief）

为**单人销售的本人**设计 CRM 模块内部 UI：手机（Android，现场单手用）为主，Windows 桌面为辅。
已具备：6 类实体（线索/客户/联系人/项目/合同/收款）+ 关系链 + 每类阶段 + 金额/关键日期 +
自定义字段 + 带时间的跟踪记录 + 关联知识库页面 + AI 记忆卡；CRM 事件已写入全局时间线并出现在日历当天视图；
首页已有全局"记录流"。不求企业级全功能（无多人协作/权限）。

## 二、探索维度

| 维度 | 探索的取值 |
| --- | --- |
| ① 导航中心 | 客户 Hub / 流程管道 / 活动时间流 / 搜索命令 |
| ② 信息密度 | 宽松聚焦 ↔ 高密度仪表盘 |
| ③ 交互节奏 | 确认式 / 快速拖拽 / 手势环境式 / 键盘与无障碍优先 |

四个方案分别占据四个"最大差异角落"（不做彼此的平均值）。

## 方案 A：「客户全貌」— 客户为中心的 Hub

**角落**：客户 Hub ／ 宽松聚焦 ／ 确认式

**概述**：CRM 只有一层真实结构——**客户**。打开 CRM 就是客户列表（一行一客户：名称、等级、最近一次互动、未收金额），
点进客户就是"这个人的全部"：项目、合同、收款、联系人、跟踪记录、AI 记忆依次成节，每节默认只露 3 条 + "更多"。

**布局**：客户列表页 = 顶部搜索 + 等级筛选 + 卡片列表（卡片高 88，左侧等级色条，右侧未收金额）；
客户详情页 = 一张"客户头卡"（名称/等级/行业/负责人隐藏）+ 6 个折叠节（项目/合同/收款/联系人/跟踪/AI 记忆），
每节标题右侧一个"＋"，点击展开后才是明细。全局的线索/联系人/合同/收款作为**独立次级入口**放在客户列表右上角"⋮ → 全部线索/全部合同…"。

**交互**：记跟进 = 客户详情底部常驻"记一笔"输入条 → 选类型（电话/拜访/…）→ 保存（3 步，含一次确认，
与日历/时间线自动同步）；推进阶段 = 头卡上的阶段大字，点开全屏阶段选择（每个选项 56px 高）→ 确认；
查合同/收款 = 客户详情里向下滚动，不需要跳页。

**视觉**：克制的 M3：卡片圆角 12、`surfaceContainerLow` 底、无阴影；标题 17/600，正文 15，次要信息浅灰但**不加小字**；
强调色只用在"未收金额"与"今天要跟进"两处；阶段用中性色块，避免整页彩虹。

**关键时刻**：首次进入 = 一个大按钮"添加第一个客户"；空态 = 客户名占位卡 + "先记下公司名也行"；
错误 = 红字 + 明确下一步（"号码格式不对，点这里改"）；成功 = 底部轻提示"已记入 3 月 12 日"。

**优势**：① 与真实销售心智一致（一切围绕客户），上手零学习成本；② 客户全貌一屏可滚动看完，查合同/收款不用跳页；
③ 大目标、无手势、单手可达，现场和老年/视力一般的人都能用。

**代价**：① 看不到"漏斗全局"（本周进了多少线索、卡在哪一阶段）；② 跨客户比较（谁的合同快到期）需要另做视图；
③ 客户多时列表会成为唯一的检索方式。

**最适合**：以"存量客户维护 + 现场记录"为主、客户数量在几十到一两百的销售。

## 方案 B：「漏斗流」— 流程管道优先

**角落**：流程管道 ／ 高密度仪表盘 ／ 快速拖拽

**概述**：CRM 首页就是一条**横向阶段看板**，把"线索 → 项目 → 合同 → 收款"当成一条流水线；
卡片在列之间移动就是推进进度，客户/联系人退回"档案抽屉"从卡片侧滑打开。

**布局**：首页顶部是 4 段切换（线索/项目/合同/收款），下面是横滑的**阶段列**（每列宽 78% 屏宽，列头显示阶段名+数量+金额合计）；
列内卡片一行信息：标题、客户名、金额、关键日期（逾期描红）；客户/联系人不是列，而是卡片右上角头像 → 侧滑抽屉；
底部导航不变，但 CRM 页不再有"列表页"这一层。

**交互**：推进阶段 = 长按卡片拖到下一列（松手即确认，乐观更新 + 触觉反馈，失败回滚并提示）；
记跟进 = 卡片右下角"+""→ 半屏速记（默认"电话"，一行文字输入，回车即存）；
线索转项目 = 在"线索"里拖到"已转项目"列 → 自动弹出项目创建向导（预填客户/联系人/备注，3 个字段确认）；
查合同收款 = 合同/收款本身就是另外两段看板的列。

**视觉**：信息密度高：卡片高 64、字号 14；**阶段用色彩语义**（新线索灰、报价蓝、投标紫、已成交绿、流失深灰），
列头有小色点与合计金额；金额用等宽数字对齐，逾期日期红点；牺牲留白换取"一屏看全"。

**关键时刻**：首次进入 = 空列 + 列头虚线框"把线索拖到这里"；空态 = 每列一行提示；
逾期态 = 卡片红边 + 顶部"3 个逾期"横幅；成功态（成交）= 卡片飞入"已成交"列 + 全屏绿色对勾 1 秒 + 金额合计滚动增长。

**优势**：① 一眼看清"整个盘子卡在哪"，这是 CRM 最有价值的视图；② 推进阶段变成"拖一下"，几乎零操作成本；
③ 金额合计/逾期直接可见，适合做周复盘。

**代价**：① 手机窄屏上列内卡片很小，误触与疲劳；② 学习成本最高（要理解"当前在哪个阶段视图"）；
③ 客户维度的信息被拆散，"看某个客户全貌"要绕一圈。

**最适合**：项目型/工程型销售（每单金额大、阶段多、需要盯漏斗和逾期）。

## 方案 C：「跟进流」— 活动与时间优先

**角落**：活动时间流 ／ 中等密度可扫读 ／ 手势环境式

**概述**：CRM 首页不是实体清单，而是**"今天该跟进谁 + 最近发生了什么"的时间流**：
每条 CRM 事件（电话/拜访/会议/…）就是一行，左侧时间、右侧实体与内容；实体本身退到"点开一行才出现"的详情。

**布局**：首页分三段——置顶"今天/逾期"（红/橙点，最多 3 条，可滑走）、"最近 7 天"事件流（一行一条，含实体类型徽标+实体名+一句话）、
底部常驻"记一笔"输入条（悬浮，56px）；实体入口在右上角"档案"（线索/客户/联系人/项目/合同/收款 六个 chip，点入即筛选事件流）。
因为每条事件本来就进全局时间线，这一页与日历的"当天视图"是同一份数据的两个入口。

**交互**：5 秒记一条 = 点底部输入条 → 打字/语音 → 自动带出"最近提到的实体"智能建议（或输入 @客户名）→ 回车即存（无二次确认，可撤销 5 秒）；
从事件跳实体 = 点行左侧徽标；"今天该跟进谁" = 由"关键日期临近 + 最近一次跟进间隔"自动生成，可左右滑动"推迟到明天/完成"；
线索转项目 = 在事件里长按线索徽标 → "转为项目"。

**视觉**：白底、几乎无卡片（用分割线 + 时间轴竖线），事件类型用小圆点色彩语义；正文 15、时间 12 浅灰；
实体类型用两字徽标而不是图标（"客户/项目/合同"），中文可读性优先；整体像"微信聊天记录 + 日历"。

**关键时刻**：首次进入 = 顶部提示"记第一条跟进，之后这里会自动排今天该联系谁"；
空态 = 输入条高亮闪烁一次；逾期态 = 顶部橙色横条"2 条逾期 →查看"；成功态 = 行内插入动画 + 触觉反馈。

**优势**：① 最贴"现场随手记"的场景，记录动线最短；② 与日历/时间线天然同源，不需要额外维护两套视图；
③ 事件流让"这个客户最近发生了什么"自然浮现。

**代价**：① 没有"结构化全景"（金额合计、阶段分布都看不到）；② 靠时间排序，找"某个合同条款"要靠搜索；
③ 手势多（滑走、撤销），对不熟手势的人不友好。

**最适合**：高频外出拜访、以"聊天记录式跟进"为主的销售；也适合把 CRM 当"客户记忆"而非"销售报表"的人。

## 方案 D：「输入即达」— 命令/搜索优先 + 无障碍优先

**角落**：搜索命令 ／ 低密度大目标 ／ 键盘手势 + 确认；**无障碍优先（对比度、字号、色盲友好、TalkBack）**

**概述**：CRM 主页极简到只有"一个输入框 + 最近的几条 + 三个大按钮"。用户不需要在层级里找东西：
**输入即达**——打字/语音说"张三 跟进"，系统直接给出动作或实体候选；选中后进入"单卡聚焦页"，一屏只呈现一件事。

**布局**：上半屏 = 一个大输入区（高 72，圆角 16，提示"说一句或打几个字"），下方紧跟实时结果分组：
实体（客户/项目/合同…）、动作（"给四川石化记跟进"）、新建（"新建线索 …"）；
下半屏 = "最近 3 条 + 置顶 2 个今日动作"，其余全部收入搜索结果。单卡聚焦页 = 一张通栏卡，
字段一行一个、每行 56px、字号 17；底部常驻输入条把内容自动挂到当前聚焦实体。
全局无障碍：正文 ≥17、次要信息 ≥15 且中灰（对比 ≥4.5:1）、所有可点区域 ≥48×48、
阶段与状态用"文字+图标"表达而非纯颜色，TalkBack 焦点顺序按"标题→字段→动作"。

**交互**：记跟进 = 点输入条 → 一句话 → 选实体（候选置顶）→ 保存（可全程语音）；
推进阶段 = 聚焦页顶部大字阶段（如"报价"）→ 点开全屏选项（每项 60px 高、带说明）→ 确认；
线索转项目 = 输入"转项目 四川石化"直接出动作。

**视觉**：极简黑白灰 + 一个强调色；卡片圆角 16、无阴影；不用小字号和浅灰做信息分层（改用字重与间距）；
所有图标配文字标签（不用纯图标按钮）。

**关键时刻**：首次进入 = 5 步上手清单（建客户→建联系人→建项目→记跟进→看日历），点一步做一步；
空态 = 大按钮"说一句，我来归档"；错误 = 红字 + "重试/改成文字"两个大按钮；成功 = 全屏对勾 1 秒 + 触觉。

**优势**：① 单手/嘈杂/边走边用最稳（目标大、无手势）；② 无障碍最佳，长期使用眼睛负担最小；
③ 记录与查找合并成"同一件事"，不需要先想"该去哪一页"。

**代价**：① 没有全局态势视图（无漏斗、无合计）；② 依赖搜索，实体多时需要记得名字；
③ 大字号意味着单屏信息量少，整理型工作（批量改字段）效率低。

**最适合**：现场、车上、夜间单手记录；对本机视力/精细操作有顾虑的使用者。
