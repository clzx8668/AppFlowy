## 四、Windows 桌面端构建（已验证）

```powershell
# 1) 固定使用 Flutter 3.27.4
$env:Path = "D:\flutter\3.27.4\bin;" + $env:Path
# 2) 关键：本机 PUB_HOSTED_URL 指向国内镜像，会污染 pubspec.lock，构建前必须清掉
Remove-Item Env:PUB_HOSTED_URL -ErrorAction SilentlyContinue

cd E:\Dev\AppFlowy\frontend
# 3) 编译 Rust 内核 → dart_ffi.dll，并拷贝到 appflowy_flutter\windows\flutter\dart_ffi\
cargo make --profile development-windows-x86 appflowy-core-dev
# 4) 代码生成：本地化 key、freezed、flowy 图标
cargo make code_generation

cd appflowy_flutter
flutter pub get
flutter run -d windows          # 开发调试；或 flutter build windows --debug
```

实测耗时（首次全量、16 线程）：Rust 内核 ~11 分钟（先 `cargo build` 预热）+ cargo-make 任务 ~8 分钟；
Dart/C++ 端 `flutter build windows --debug` ~4 分钟。产物：`frontend\appflowy_flutter\build\windows\x64\runner\Debug\AppFlowy.exe`
（同目录含 `dart_ffi.dll`，约 116 MB，debug 带符号）。已实际启动该 exe，进程稳定驻留，Rust 后端正常初始化。

## 五、Android：为什么 Rust 内核必须放到 WSL 编译

`cargo make --profile development-android appflowy-core-dev-android` 的两条路在 Windows 上都走不通：

1. **该任务脚本本身是 bash**（`frontend/scripts/makefile/mobile.toml` 中 `script_runner = "@shell"`，
   内含 `if [ ... ]`），在 Windows 上直接报 `'fi' is not recognized`，命令退化成 `--release` 分支。
2. **Rust 依赖里有非可选的 vendored OpenSSL**（`flowy-sqlite` → `openssl-sys`），
   即使 `--features dart` 也会被拉进来；openssl-src 在 Windows 上用 `linux-aarch64` 目标配置时要求
   "produce Unix like paths" 的 Perl：
   - 本机 Git 自带 msys perl：缺 `Locale::Maketext::Simple` 等模块；
   - Strawberry Perl（MSWin32）：直接拒绝，提示 *This perl implementation doesn't produce Unix like paths*。

所以 Android 的 Rust 内核改为在 **WSL Ubuntu** 内编译（与上游 CI 的 Linux 环境一致），
Flutter/Gradle 侧仍在 Windows 上进行，两端通过 `jniLibs` 目录衔接。

WSL 侧一次性准备（已在本机完成，脚本已固化到仓库 `doc/tools/`）：

```powershell
# 用户级操作，无需 sudo 密码（WSL 可直接用 root）
wsl -d Ubuntu -u root -- bash /mnt/e/Dev/AppFlowy/doc/tools/wsl-android-env-setup.sh
# 内含：apt 依赖(build-essential/clang/libclang-dev) + Rust 1.85 + android target
#       + cargo-ndk 3.5.4 + Linux 版 NDK r24（腾讯镜像下载）
```

后续每次构建 Android Rust 内核：

```powershell
wsl -d Ubuntu -u root -- bash /mnt/e/Dev/AppFlowy/doc/tools/android-rust-build.sh
```

该脚本做的事：`cargo ndk -t arm64-v8a -o ./jniLibs rustc --crate-type cdylib
--features "dart,openssl_vendored" --package=dart-ffi`（与上游 `setup-crate-type` 等价，但不改 `Cargo.toml`，
工作区保持干净）→ 把 `rust-lib/jniLibs/arm64-v8a/libdart_ffi.so` 拷到
`frontend/appflowy_flutter/android/app/src/main/jniLibs/arm64-v8a/`。

实测：首次全量 6 分 37 秒（含 rocksdb/openssl 等 C/C++ 依赖），改代码后增量重编约 1.5 分钟；
产物 `libdart_ffi.so` 约 115 MB（debug 带符号）。

## 七、踩过的坑（务必遵守）

1. **不要在设置 `PUB_HOSTED_URL`（pub.flutter-io.cn 镜像）的情况下执行 `flutter pub get`**。
   lock 里记录的是 `pub.dev` 源，镜像来源不同会让 pub 全量重解析并升级依赖：
   `flutter_math_fork` 从 0.7.3 升到 0.7.4 后，Windows 构建会失败（`RenderObjectWithLayoutCallbackMixin` 在 Flutter 3.27.4 不存在）。
   正确做法：`Remove-Item Env:PUB_HOSTED_URL` 后再 `flutter pub get`，`pubspec.lock` 保持不变。
   若已将 lock 改坏：`git restore frontend/appflowy_flutter/pubspec.lock` 后重跑。
2. Flutter 版本必须是 **3.27.4**；用 3.41.x 连 `flutter pub get` 都过不去（`leak_tracker` 版本冲突）。
3. `bindgen` 需要 libclang，Windows 上最容易踩：报 `Unable to find libclang` 时检查 `LIBCLANG_PATH`。
4. Windows NDK 只带 `windows-x86_64` prebuilt，WSL 不能复用，必须单独装 Linux 版 NDK。
5. `frontend/appflowy_flutter/cargokit_options.yaml`（`use_precompiled_binaries: true`）在本版本**没有任何引用**，
   本仓库未接入 cargokit；内核产物由 cargo-make / cargo-ndk 自行编译，勿据此判断会拉上游预编译库。
6. 首次 Rust 全量编译会拉 GitHub 上的 `AppFlowy-Collab`、`AppFlowy-Cloud`、`rust-rocksdb`（含 rocksdb 子模块），
   耗时较长且必须能访问 github.com；国内网络下建议保持代理可用。
7. **Gradle/JDK**：项目用 Gradle 8.1，与 Android Studio 的 JBR 21 不兼容（报 “Gradle version is incompatible with
   the Java version”），已通过 `flutter config --jdk-dir` 固定到本机 Temurin 17。
8. **`appflowy_backend` 模块仍引用已停服的 `jcenter()`**；Gradle 会回落到 Maven Central，
   网络抖动时会出现 `Could not HEAD https://repo1.maven.org/...`，Flutter 会自动重试一次，通常重试即可成功；
   若反复失败，给 Gradle 配国内 Maven 镜像（aliyun）即可。
9. **WSL 里交叉编译 Rust 必须给 bindgen 传 NDK sysroot**，否则会误读宿主机 glibc 头文件，报
   `'bits/libc-header-start.h' file not found`。`doc/tools/android-rust-build.sh` 已设置
   `BINDGEN_EXTRA_CLANG_ARGS_aarch64_linux_android="--target=aarch64-linux-android21 --sysroot=..."`。
10. WSL 的 `cargo-ndk` 必须是 **3.5.4**（4.x 要求 rustc ≥ 1.86，与本项目锁定的 1.85 冲突）。
