## 2026-09-23 · 步骤①：本地优先模式（跳过登录 + 隐藏云端入口）

**背景**：上游 0.11 默认连接 AppFlowy Cloud，当前网络下 `appflowy.cloud` 被 Cloudflare 403，
真机启动后卡在登录页无法进入工作区；且产品规划已明确放弃 AppFlowy Cloud、走全本地 + WebDAV 快照同步。

**做法**：新增一个显式开关 `kLocalFirstMode`，集中控制"全本地优先"，其余 4 处只在既有条件分支上收口。

| 文件 | 改动 |
| --- | --- |
| `lib/env/local_first.dart`（新增） | 本地优先开关 `kLocalFirstMode`，是本次唯一"总闸"；置 `false` 即回退到上游行为 |
| `lib/main.dart` | 启动改为 `runAppFlowy(isAnon: kLocalFirstMode)`：匿名模式自动创建/复用本地用户，不请求云 |
| `lib/env/cloud_env.dart` | `AppFlowyCloudSharedEnv.fromEnv()` 在本地优先模式下直接返回 `AuthenticatorType.local` 与空云配置；于是 `isAuthEnabled` / `isAppFlowyCloudEnabled` 均为 false，云同步任务不初始化、账号登录/订阅/协作入口按上游既有条件自动隐藏 |
| `lib/user/presentation/screens/splash_screen.dart` | 未启用云鉴权时不再把移动端强制跳到登录页（上游 `isAuthEnabled \|\| UniversalPlatform.isMobile` 会让本地模式在手机上卡在登录页） |
| `lib/workspace/presentation/settings/widgets/settings_menu.dart` | 未启用云时隐藏"云服务设置"菜单项 |
| `lib/mobile/presentation/home/tab/space_order_bloc.dart` | 未启用云时隐藏移动端 `Shared`（协作/共享）标签页，并让被隐藏的默认标签回退到首个可见标签，避免 `TabController` 初始索引越界 |
| `doc/tools/android-rust-build.sh` | 修复：不再清空 `jniLibs` 目录（会删掉 CMake 放入的 `libc++_shared.so`，导致真机 `dlopen failed: library "libc++_shared.so" not found`），并在缺失时自动从 NDK 补齐 |

**验证**（荣耀 ELZ-AN10，Android 14）：

- 启动日志：`restart AppFlowy: isAnon: true`、`cloud setting: authenticator: AuthenticatorType.local`、
  云配置全空 `{base_url: , ws_base_url: , gotrue_url: ...}`，无任何云请求、零异常；
- 启动耗时从 4.2s 降到 0.8s（少了云相关初始化）；
- 界面：直接进入本地工作空间（空间/最近/收藏），可正常新建与编辑笔记，重装 APK 后本地数据保留；
- 回归：`dart analyze`（改动文件）无告警；`flutter build windows --debug` 通过。

**后续待办**（本步骤遗留）：

1. 桌面端侧边栏「Shared/发布站点/邀请成员」等云协作入口尚未逐一核对隐藏。
2. 移动端首页设置弹窗（`HomePageSettingsPopupMenu`）内的云相关项待核对。
3. 登录/注册路由与页面代码保留未删除（按规约"只隐藏不删除"）。

## 2026-09-23 · 步骤②：现有模块复用分析 + 五个扩展包骨架

**分析文档**：新增 `doc/现有模块复用与扩展分析.md`，结论要点：

- 类 Notion 块编辑器 / 双链 / 块引用 → **直接复用**（不重写编辑器）；
- 视图插件系统（`PluginType` / `registerPlugin` / `PluginBuilder`）与自定义块注册点
  （`editor_configuration.dart` 的 `buildBlockComponentBuilders`）→ **新增页面与自定义块不用改内核**；
  但后端 `ViewLayoutPB` 只有 5 种布局，**新增"视图布局"需要改 Rust，属于红线**；
- AI → 有 `AIRepository` 抽象层，**接口复用、实现可替换**（`app_ai_ext` 只做模型接入与记忆编排）；
- 闪念 / 日记 / CRM / WebDAV 快照 → 上游**完全没有**，必须自研；WebDAV 可复用 `ApplicationDataStorage`
  路径与 `archive` 打包，日期解析可复用 `DateService.queryDate`。

**五个扩展包骨架**（`frontend/appflowy_flutter/packages/`，均为 path 依赖、名字与蓝图一致）：

| 包 | 骨架内容 |
| --- | --- |
| `app_flash_note` | `FlashNoteCapture` 捕获入口契约（悬浮/下拉/快捷键）、模块标识 |
| `app_diary_time` | `DiaryEntryMeta` 元数据模型、`DiaryService`（打开/创建当日日记、区间索引） |
| `app_crm_biz` | `CrmCustomer` 客户模型、`CrmRepository` 仓储契约（独立业务库） |
| `app_webdav_sync` | `WebDavConfig`、`SnapshotInfo`、`WebDavSyncService`（打包/上传/列举/下载） |
| `app_ai_ext` | `MemoryAiService`（摘要/标签/周期回顾）、`AiDigestResult` |

**接入方式**：`pubspec.yaml` 加 5 个 path 依赖；新增 `lib/extensions/extension_registry.dart` 作为 App 与
扩展包之间唯一出入口（后续路由、自定义块、插件注册、AI 实现替换、入口挂载都集中在此），
并在 `PluginLoadTask` 中调用 `ExtensionRegistry.registerAll()` 完成登记。

**验证**：`flutter pub get` 通过（新增 5 个依赖）；`dart analyze`（扩展包 + 注册表 + 改动文件）零告警；

**新增 `app_flash_note` 模块（v0 闭环已在荣耀真机跑通）**：

| 组成 | 说明 |
| --- | --- |
| `FlashNote` / `FlashNoteRepository` | 闪念表 `flash_notes`（id/text/created_at/document_id/archived），业务库读写 |
| `FlashNoteService` | 捕获→入库→落成文档→回看；归档/删除；文档创建失败时原文仍安全留在库中 |

- 带正文建页：`ViewBackendService.createView(initialDataBytes:)`，`initial_data` 必须是

- 打开发文档：`ViewBackendService.getView(viewId)` + 移动端 `context.pushView(view)`。

**关键发现（之前的"页面不可见"根因）**：**分区（section）不匹配**。
移动端首页列表渲染的是 **Public 分区**（手机端「+」新建页面传的也是 `FolderSpaceType.public`），
而容器最初建在 Private 分区，所以创建成功却不出现在列表里；父节点（`parentViewId`）从头到尾都是对的。

**代码修正**：

- `ContainerRepositoryImpl`：容器改为建在 `ViewSectionPB.Public`，列举也读 `getPublicViews()`；
- 容器标记继续写 `view.extra`（`af_container` / `af_module` / `af_icon` / `af_created_at`），
  用上游同一套「新建页面」路径 `WorkspaceService.createView(...)`；
- 闪念记录挂在「闪念」容器下：`ViewBackendService.createView(parentViewId: 容器id, initialDataBytes: ...)`；
- 移动端首页就绪时自动 `ensureDefaultContainers()`（幂等），无需任何手动操作。

**真机验证（荣耀 ELZ-AN10，05:14–05:15）**：

- 页面树出现 `闪念 / 笔记 / CRM / AI` 四个顶层容器 ✔
- 捕获一条闪念后，「闪念」容器出现子节点（可展开）✔

**遗留**：早期在 Private 分区创建的 4 个同名容器成为不可见的历史数据（不影响使用，后续可加一次性清理脚本）；
真机上仍有测试页面与测试闪念，可在 App 内删除。

### 步骤⑧ 真机验证结论（2026-09-24 22:00–22:12）：**v0 自定义块类型不可用，入口已暂时收起**

真机实测（荣耀 ELZ-AN10）：

1. 手机端「+」块面板需要**单独接线**（它有自己的硬编码列表 `add_block_menu_item_builder.dart`，
   不走斜杠菜单的 `slashMenuItemsBuilder`）——已接入，「生活记录」能出现在块列表 ✔；
2. 点击后**插入成功、渲染正确**（卡片：日期 + 生活记录 + 心情/天气/地点 chips）✔；
3. **杀掉应用重开同一篇日记后，该块消失** ✗ —— 说明"Block.ty 是 String"只保证**存储结构**可容纳自定义类型，
   但 AppFlowy 文档的**运行时写入/同步路径并不接受未知块类型**（我之前只核对了 entities.rs，未覆盖同步写入路径，
   判断有偏差）。Rust 日志中没有相关报错（该日志级别不记录块写入），因此是从结果反推的。

**处置**：为避免给用户暴露"点了会消失"的功能，已把两处入口（斜杠菜单、移动端「+」面板）**暂时收起**
（代码保留在 `app_diary_time` 包内，并加注释说明）。当前构建与仓库状态正常。

**下一步方案（改为蓝图本就允许的形态）**：把生活元数据做成
**「标准块类型 + 自定义 payload + 覆写该类型的构建器」**：

- 节点类型沿用内核支持的 `callout`（或 `paragraph`），数据写在该节点的 attributes（`af_life_meta: {...}`）；
- 在 `editor_configuration.dart` 里用我们自己的构建器**覆盖** `CalloutBlockKeys.type`：当节点带 `af_life_meta` 标记时
  渲染我们的生活记录卡片，否则回退上游 `CalloutBlockComponentBuilder`；
- 这样既保留"块级 payload"的形态，又完全走内核已支持的块类型，落库/同步安全。
