# 现有模块复用与扩展分析（二次开发前置调研）

> 目的：在动手写扩展包之前，逐个确认「哪些能力上游已经具备、能直接用」「哪些只需要加扩展点」「哪些必须自研」，
> 避免重复造轮子，也避免误改内核。
> 结论依据：上游 AppFlowy 0.11.4 代码实读（文件路径均为 `frontend/appflowy_flutter/` 或 `frontend/rust-lib/` 下）。

## 一、总览结论

| 需求（蓝图五大模块） | 上游是否已有 | 结论 |
| --- | --- | --- |
| 类 Notion 块编辑器（文档、块、双链、块引用） | ✅ 完整具备 | **直接复用**，不重写编辑器 |
| 结构化数据（表格/看板/日历视图） | ✅ 具备（database2 内核 + 三种视图） | **能力复用，但 UI 不外露**（蓝图 Windows 端禁止原生数据库/看板入口），仅按需借用其内核能力 |
| AI（写作辅助、聊天、模型选择、提示词） | ✅ 具备，且有 `AIRepository` 抽象层 | **接口复用、实现可替换**（为 `app_ai_ext` 的本地/自选模型留好接缝） |
| 闪念速记 | ❌ 没有 | **自研页面 + 复用文档创建 API** |
| 时间日记 / 日历回溯 | ❌ 没有（无 daily note / journal 任何代码） | **自研页面 + 复用文档 API 与日期解析** |
| CRM 客户业务 | ❌ 没有 | **自研页面 + 独立业务库** |
| WebDAV 快照同步 | ❌ 没有（只有 AppFlowy Cloud 同步与数据库 CSV/raw 导出） | **自研**（`archive` 已有依赖可打包） |
| 本地优先 / 跳过登录 | ⚠️ 上游有匿名（local）模式，但默认走云 | 已完成（见《二次开发改动记录》步骤①） |

## 二、可直接复用的关键能力（含接入点）

### 1. 视图/页面插件系统（新增页面的官方接缝）

- 抽象：`lib/startup/plugin/plugin.dart` —— `Plugin` / `PluginBuilder` / `PluginConfig` / `PluginWidgetBuilder`。
- 注册：`lib/startup/tasks/load_plugin.dart` → `registerPlugin(builder: ...)`；
  上游已注册 blank / trash / document / grid / board / calendar / databaseDocument / chat。
- 取用：`makePlugin(pluginType: ...)`、`pluginBuilders()`（新建页面菜单就是它驱动的）。
- 结论：**新增"页面类型"不用改内核**，在 `load_plugin.dart` 追加注册即可（属适配层）。
- 限制：`PluginType` 是上游固定枚举，且后端 `ViewLayoutPB` 只有 Document/Grid/Board/Calendar/Chat；
  **新增一种"视图布局"需要改 Rust 后端，属于红线**。因此闪念/日记/CRM 采用
  「自研页面 + 复用 Document 视图承载正文 + 业务元数据存自有存储」的组合，而不是新增 layout。

### 2. 文档/块能力（真块、双链、块引用）

- 编辑器由外部包 `appflowy_editor` 提供，节点类型是开放字符串（`Node.type`），**支持自定义块**。
- 块注册接缝：`lib/plugins/document/presentation/editor_configuration.dart:63`
  `buildBlockComponentBuilders({context, editorState, styleCustomizer, slashMenuItemsBuilder, ...})`
  返回 `Map<String, BlockComponentBuilder>`；上游的每个块（callout/toggle/table/image/math…）都在这里登记。
- 斜杠菜单接缝：`slashMenuItemsBuilder`（`lib/plugins/document/presentation/editor_plugins/slash_menu/`）。
- 结论：**自定义生活块（心情/天气/位置/倒计时/CRM 卡片）可以在扩展包里实现 builder + slash 项**，
  只需在 `editor_configuration.dart` 挂一行注册（适配层允许的"只新增"）。
- 数据落点：块属性写在节点 `attributes`（等价于蓝图说的 block payload），二进制资源只存路径（上游图片/文件块已是此惯例）。

### 3. 文档与视图的创建/读取 API（业务模块建页面的基础）

- `ViewBackendService.createView(...)`（`lib/workspace/application/view/view_service.dart`）：
  指定 parent、name、layout、section 等创建页面；`SpaceBloc.createPage`、`SidebarSectionsBloc` 是其在 UI 层的用法。
- 读取/检索：`flowy-search`（Rust）+ 前端 `lib/workspace/...`；命令面板可搜索全部页面。
- 结论：闪念/日记/CRM 的正文都可以直接建成普通 Document 页面，从而**天然获得块能力、双链、搜索、回收站**。

### 4. AI 能力（写作辅助 / 聊天 / 提示词 / 模型选择）

- 抽象层：`lib/ai/service/appflowy_ai_service.dart` → `abstract class AIRepository`（流式补全、内置提示词、数据库提示词）。
- 注册：`lib/startup/deps_resolver.dart` → `getIt.registerFactory<AIRepository>(() => AppFlowyAIService())`。
- 已有 UI：`lib/ai/widgets/**`（提示词输入、模型选择）、`lib/plugins/ai_chat/**`（AI 聊天页，作为 `PluginType.chat` 注册）。
- 本地模型：Rust `flowy-ai` 已支持 Ollama 本地模型（设置页有本地模型选择、模型状态检查）。
- 结论：**`app_ai_ext` 不需要重写 AI**；它的职责是：
  (a) 提供我们自己的 `AIRepository` 实现（接自选/本地模型，替换/包装 `AppFlowyAIService`）；
  (b) 提供面向"记忆体系"的上层编排（如：日记/闪念的自动摘要、标签、回顾、问答检索）。

### 5. 日期与日历

- NLP 日期解析：`lib/date/date_service.dart` → `DateService.queryDate('明天')`（Rust `flowy-date`）。
  **闪念/日记的"今天/昨天/下周一"快速录入可直接用**。
- 日历视图：Rust `flowy-database2` 的 Calendar 视图 + 前端 `lib/plugins/database/calendar/**`
  （`CalendarPluginBuilder`）。它是"数据库视图"，依赖先有 database 视图对象。
- 结论：日记的月历**自研更合适**（蓝图要求 iOS 级极简月历 + 每日日记页，且禁止暴露原生 database UI）；
  但"日期解析"与"按日期字段查询/排序"可借用内核。

### 6. 存储与数据目录（WebDAV 快照的基础）

- 应用数据目录：`ApplicationDataStorage.getPath()`（`startup.dart` 中已用），桌面端实测为
  `%APPDATA%\io.appflowy\AppFlowy\data_dev\`，内含：
  - 用户级 Core 库：`<uid>/flowy-database.db`（SQLite）
  - CRDT 协作库：`<uid>/collab_db/`（RocksDB）
  - 索引：`<uid>/indexes/`、向量库 `vector.db`、缓存 `cache.db`、`image_cache/`
- 结论：**WebDAV 快照 = 打包上述目录**（Core 库 + 业务库 + 附件），与蓝图"双库 + 附件一起快照"一致。
- 风险：打包前需保证 SQLite/CRDT 一致性（WAL）。上游没有现成的"冻结数据库"API，
  且我们不能改 Rust；可行做法是：暂停前台写入与后台任务 → 连同 `-wal/-shm` 一起拷贝 →
  或调用既有 API 让后台服务静默后再拷贝。此项在 `app_webdav_sync` 实现阶段需做专项验证。

### 7. 已有但**不可直接用**的能力（说明原因）

| 能力 | 原因 |
| --- | --- |
| AppFlowy Cloud 同步 | 蓝图明确放弃；且当前网络下被 Cloudflare 403 |
| 原生 database 视图（grid/board/calendar） | 蓝图 Windows 端列为禁止功能；CRM/日记需要自己的业务表达与统计 |
| 团队/空间/邀请/分享发布 | 单工作空间 + 本地优先，已隐藏入口（步骤①） |
| 上游备份/快照 | 不存在；只有数据库 CSV/raw 导出（`BackendExportService`） |

## 三、五个扩展包的定位与实现策略

统一原则：**扩展包只做 UI 与业务编排，一切块/文档能力走内核既有 API；业务数据走独立存储；不新增 Rust 代码。**

| 扩展包 | 复用 | 自研 | 存储 |
| --- | --- | --- | --- |
| `app_flash_note` 闪念速记 | 文档创建 API、编辑器、搜索、`DateService` 解析 | 极速捕获 UI（移动端悬浮/下拉/快捷输入；Windows 全局快捷键+速记窗）、收件箱视图、批量整理 | 正文=普通 Document；元数据（来源、标签、捕获时间）存业务库 |
| `app_diary_time` 时间日记 | 文档 API、`DateService`、双链/块引用 | 极简月历、每日日记页、时间线回溯、生活元数据块 | 正文=按日期命名的 Document（标题即日期）；元数据（心情/天气/位置）存业务库并在文档中被引用 |
| `app_crm_biz` CRM 业务 | 文档 API（拜访记录/方案正文）、块引用、搜索 | 客户档案、跟进记录、筛选统计、Windows 表格视图、移动端现场快录 | **独立业务库**（不污染 Core 库）；客户↔文档用 view id 关联 |
| `app_webdav_sync` WebDAV 快照 | `ApplicationDataStorage` 路径、`archive` 打包、`http` 客户端 | 快照打包/冻结、WebDAV 上传下载、版本哈希、差异比对、冲突人工选择 | 快照文件（zip）+ 本地快照索引 |
| `app_ai_ext` AI 扩展 | `AIRepository` 抽象与既有 AI UI、Ollama 本地模型 | 自有模型接入实现、记忆体系编排（摘要/标签/回顾/问答）、提示词模板 | 提示词与嵌入索引（后续），先复用内核向量库 |

### 自定义块（心情/天气/位置/倒计时/CRM 卡片）实现方式

1. 在扩展包内定义节点类型常量（如 `mood_block`）与 `BlockComponentBuilder`；
2. 提供斜杠菜单项与快捷键（`slashMenuItemsBuilder` 扩展）；
3. 在 `editor_configuration.dart` 的 builder map 上挂载（**唯一需要动到上游文件的一行**，属适配层"只新增"）；
4. 数据全部写节点属性（payload），二进制只存路径；渲染缺失时降级为普通段落，保证快照/同步安全。

## 四、落地顺序建议（与蓝图一致）

1. **骨架先立**：五个包建立 + path 依赖接入 + 扩展注册点（本轮已完成，见下）。
2. `app_flash_note` 先跑通"捕获→落成文档→回看"最小闭环（安卓优先）。
3. `app_diary_time` 打通"月历→每日日记→生活块"，复用日期解析。
4. `app_crm_biz` 落业务库与客户档案，移动端现场录入 + Windows 表格。
5. `app_webdav_sync` 做快照闭环（打包→上传→校验→冲突处理），先全量后增量。
6. `app_ai_ext` 先接自有模型与摘要/标签，再谈问答与长期记忆。
