# CRM 内部 UI — 设计定稿（A + C 合成，代号「方案 F」）

> 产出方式：`design-interface`（探索四方向 → 用户选 A+C）→ `grill-me`（六问定边界）→ 本定稿。
> 探索过程与对比矩阵见 [CRM手机端UI设计方案对比.md](../CRM手机端UI设计方案对比.md)。

## 一、选定的设计：方案 F（A 的底座 + C 的动线）

**一句话**：CRM 以**客户**为重心（A），把"今天该跟进谁 / 最近发生了什么"做成**时间敏感动线**（C），
尽量复用已有实现（六个滑动标签、实体详情分节、`crm_events`、`extra` 扩展字段），不新增导航层级。

### 1. 首屏（CRM 标签默认落在「客户」）

| 区域 | 内容 |
| --- | --- |
| 顶部 | 六个滑动标签：线索 / 客户 / 联系人 / 项目 / 合同 / 收款（默认停在**客户**） |
| 置顶横条 | **「今天该跟进 N」**：最多显示 3 条，可左右滑（推迟）/ 点完成；点击展开完整清单 |
| 客户列表 | 卡片四信息位：`名称` + `等级徽标`(A/B/C) + `最近互动`（"3 天前 · 电话"）+ `未收金额`（>0 才显示）；关键日期逾期 → 名称后**小红点** |
| 排序 | 客户列表按**最近互动时间倒序**（稳定顺序，避免每次进来跳来跳去） |
| 底部 | 常驻「记一笔」（行为见第 4 节） |

其余标签（线索/项目/合同/收款）保持列表形态，但**默认按关键日期排序**（逾期/临近的浮上来）。

### 2. 「今天该跟进」的判定（三条规则）

1. **关键日期到期/逾期**：`关键日期 ≤ 今天` 且阶段不在终态 → 进清单；
2. **久未跟进**：距最近一条跟踪记录超过阈值且阶段不在终态 → 进清单。
   阈值（按类型固定，暂不做设置项）：线索 **7 天** / 项目 **14 天** / 客户 **21 天** / 合同 **30 天** / 收款 **14 天**；
3. **手动标记**：实体详情里的「⭐ 今天要跟进」开关（写 `extra.follow_up_at`）。

排序：**手动标记 > 关键日期逾期最久 > 久未跟进天数最多**；横条最多 3 条 + "还有 N 条"。
终态定义：线索 已转项目/已丢弃；项目 已成交/已流失；合同 已完成/已终止；收款不设终态（逾期需持续可见）。

### 3. 客户详情 = 客户 Hub（A）＋ 跟踪时间轴（C）

- **头卡**：名称 / 等级 / 未收金额 / **今日提醒**（若命中第 2 节规则，显示一句"关键日期已逾期 3 天"之类）；
- **六个折叠节**：项目 / 合同 / 收款 / 联系人 / 跟踪记录 / AI 记忆；**跟踪记录默认展开**，其余折叠并显示计数；
- **跟踪记录**：**按天分组的时间轴**（「今天 / 昨天 / 3月12日」+ 左侧竖线圆点，与全局时间线同一套视觉），
  顶部一行**类型筛选** chips（全部/电话/拜访/会议/微信/邮件/备注）；
  **自动事件（阶段流转/转项目）用浅灰小字、不占圆点**，人工记录才用圆点 + 类型徽标；默认展开最近 3 组，更早的"展开全部"。

### 4. 「记一笔」

| 场景 | 行为 |
| --- | --- |
| 实体详情页内 | 直接挂到**当前实体**（类型默认"备注"，顶部 chip 可切电话/拜访/会议…） |
| CRM 首页（无当前实体） | **无归属速记**：写进全局「记录流」（笔记容器），不进 CRM —— 用户明确选择 |
| 弱关联（缓解动线分裂） | 速记内容里出现 `@实体名` 时，**同时**写一条 CRM 事件（`crm_events`）并建立实体↔记录页链接（`crm_links`）；不 @ 则纯速记 |

### 5. 明确不做（Non-Goals，本轮）

1. 不做多用户 / 权限 / 负责人分配（负责人字段继续保持隐藏）；
2. 不做批量编辑与多选（手机端）；
3. 不做发票与回款的分期计划拆分（收款单保留现有字段）；
4. 不做"保存筛选器"机制；
5. 不新增导航层级（CRM 仍是底部导航的一个标签）；
6. **不改数据库结构**（唯一新增写入：`extra.follow_up_at`，走现成扩展字段机制）；
7. 不动内核 / 编辑器 / 其他模块（记录流、日历、AI 记忆保持现状）。

## 二、为什么是它（Rationale）

- **A 的底座**（客户为中心）与单人销售的心智一致，学习成本最低；客户详情一屏可滚动看完，查合同/收款不用跳页；
- **C 的动线**（时间敏感优先）解决了 A 的最大弱点——"看不到今天该干什么"：用一条置顶横条 + 久未跟进阈值补上；
- **不选 B（漏斗看板）**：手机窄屏卡片太小、学习成本最高，且用户的实际用法更偏"存量客户维护 + 现场记录"；
- **不选 D（命令优先）**：对大字号/无障碍最友好，但没有全局态势，整理型工作（改字段、看合计）效率低；其"大目标、单手可达"的优点已通过 A 的大卡片部分吸收。

## 三、实现步骤（每步都有可验证产出）

| 步 | 内容 | 验证方式 |
| --- | --- | --- |
| 1 | 首屏落到「客户」标签；客户卡片改为四信息位（等级/最近互动/未收金额/逾期红点）；列表按最近互动倒序 | 真机截图 + 数据核对（未收金额 = SUM(收款应收 − 已收)） |
| 2 | 「今天该跟进」横条（三条规则 + 排序 + 最多 3 条）＋ 详情页「⭐今天要跟进」开关（`extra.follow_up_at`） | 造三条数据（逾期合同 / 久未跟进客户 / 手动标记）→ 核对顺序与条数 |
| 3 | 客户 Hub 详情：头卡（含今日提醒）+ 六节折叠 + 跟踪记录**按天分组时间轴** + 类型筛选 + 自动事件浅灰 | 真机截图（分组标题/浅灰自动事件/筛选生效） |
| 4 | 「记一笔」：详情页挂当前实体；首页无归属速记进记录流；`@实体名` 时补写 CRM 事件 + 链接 | 真机 + 数据层核对 `crm_events` / `crm_links` 是否新增 |
| 5 | 桌面端（Windows）同构核对：同布局还是改表格视图 | 桌面截图 + 用户确认（待议） |

**遗留风险（实现时优先验证）**：
1. 阈值 7/14/21/30 天是估计值——用一两周真实数据再调；
2. "无归属速记"若不 `@` 实体，不会出现在 CRM 里；靠 `@` 弱关联缓解，需真机确认手感；
3. 卡片四信息位在 iPhone 级窄屏是否拥挤，需真机目测。

## 五、附：探索过的其他方向

- **B 漏斗流**（流程看板 + 拖拽推进）：全局态势最强、手机窄屏最吃力；
- **D 输入即达**（命令/搜索 + 无障碍优先）：单手与无障碍最佳、缺全局态势；
- 混搭备选：A+D（客户 Hub + 大字号命令搜索）可在本轮落地后作为"无障碍增强"叠加。
