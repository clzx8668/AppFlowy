# 全局完善计划（多轮执行 · 2026-09-25 起）

> 目标：把「本地优先」这条线做**一个项目、两套介质、一套信息架构**：
> 数据与状态两端一致；导航在两端都可展开 / 压缩 / 抽屉；文档、改动记录、构建基线同步收敛。
> 执行方式：本轮次内自计划 → 自实现 → 自验收（静态分析 + 双端构建 + 真机/桌面截图）→ 记录 → 提交。

## 一、现状盘点（勘察结论）

| 层 | 手机端 | Windows 端 | 结论 |
| --- | --- | --- | --- |
| 内核数据 | 内核 workspace/view/文档 CRDT | 同模型（各自本机一份） | ✅ 同一套 |
| 业务数据 | `business.db`（CRM/日记/时间线/AI 记忆/双链/快照配置） | 同表结构、同文件位置规则 | ✅ 同一套 |
| 容器语义 | 读 `view.extra` 的 `af_container / af_module / af_icon` | 同（结构对齐在两端都会跑） | ✅ 同一套 |
| 模块页面 | `LocalHomeShell` 五标签：记录 / 日历 / CRM / AI / 设置（+ 抽屉） | 上游侧栏 +「本地模块」入口（日历/CRM/AI/双链/快照） | ⚠️ 少了「记录流（首页）」入口；入口是"一堆行"而不是导航栏 |
| 侧栏形态 | 抽屉 ✅（`Scaffold.drawer`）；无压缩态（底栏已承担导航） | 上游侧栏：**展开** 或 **完全隐藏**（`MenuStatus.collapsed`）；窄屏自动变抽屉；**没有"最窄单列图标"态** | ❌ 本轮要补 |
| 主题/偏好 | `mobile_theme.dart` + `mob_prefs.dart`（SharedPreferences） | 上游外观设置（`appearanceSettings.isMenuCollapsed` 等） | ⚠️ 两套偏好各自可用，但侧栏形态没有统一开关 |

## 二、轮次安排

### 第 1 轮：侧边栏三态 + 桌面端导航对齐（本轮）

**做什么**

1. 新增 `LocalNavRail`（桌面端本地导航栏）：
   - **压缩态（默认最窄）**：宽 56，只留**单列图标** + 悬浮提示，永远可见（上游侧栏收起时不再"什么都没有"）；
   - **展开态**：一键展开上游完整侧栏（页面树 + 本地模块），保留多标签、拖拽、大纲等桌面能力；
   - **抽屉态**：一键以浮层抽屉形式打开本地导航（图标 + 文字），点遮罩关闭，任何窗口宽度都能用；
   - 项：记录流 / 日历 / CRM / AI 记忆 / 知识库双链 / 快照同步 / 设置（与移动端底栏一一对应）。
2. 桌面端补「记录流（首页）」入口 —— 移动端第一标签就是它，桌面此前**进不去**。
3. 上游布局只做**加法**：收起侧栏时给内容区留出 56px 给图标栏，其余不动。

**验收**

- `dart analyze` 无新增问题；
- `flutter build windows` 通过，启动 exe 截图确认：压缩态＝最窄单列图标、点图标能进各模块、抽屉能开合、展开态与上游一致；
- 安卓真机回归：底栏五标签、抽屉、各模块页面行为不变。

### 第 2 轮：状态与数据统一（下一轮）

- 产出《双平台状态对照表》并补进《双平台信息架构决策》。

- 文档：`项目开发目标与产品蓝图 / 整体架构设计规范 / 跨平台开发规范 / 开发环境与构建基线 / 二次开发改动记录` 对齐最新事实；
- 自检：两端构建、真机回归清单、桌面截图；

## 三、明确不做（避免跑偏）

1. 不改内核（`appflowy_editor` / Rust core / 上游页面树语义）；
2. 不把手机外壳整套搬到桌面（多标签、拖拽、大纲、批量选择仍然只属于桌面）；
3. 不动"容器＝页面"的信息架构（沿用上游可无限嵌套的页面树）；
4. 本轮不做 CRM 桌面表格视图（后续单独排）。

## 四、待办：把「本地模块」页做成上游标签页（2026-09-26 用户确认的目标）

### 现状与问题

桌面端「本地模块」6 个入口（记录流 / 日历·日记 / CRM 客户 / AI 记忆 / 知识库双链 / 快照同步）
目前是**在内容区自建一层 Navigator**里渲染的：侧栏保留、内容区切换，但**它盖在内容区最上层**，
上游那套窗口元素（标签条、`笔记 > 页面` 面包屑、分享/收藏/⋯）看不到 ——
用户判定为"弹出模式叠在内容框架上面"，**不符合原项目**。

目标：**与打开文档完全一致** —— 内容区顶部出现一个真正的标签，窗口原有元素全在，侧栏不动。

### 上游插件 API（已读实，`lib/startup/plugin/plugin.dart`）

```dart
enum PluginType { document, blank, trash, grid, board, calendar, databaseDocument, chat }
abstract class Plugin { PluginId get id; PluginWidgetBuilder get widgetBuilder; PluginType get pluginType; }
abstract class PluginBuilder {
  Plugin build(dynamic data);
  String get menuName;
  FlowySvgData get icon;
  PluginType get pluginType;
  ViewLayoutPB? get layoutType;
}
abstract class PluginWidgetBuilder with NavigationItem {
  List<NavigationItem> get navigationItems;
  Widget buildWidget({required PluginContext context, required bool shrinkWrap, Map<String, dynamic>? data});
}
void registerPlugin({required PluginBuilder builder, PluginConfig? config});
Plugin makePlugin({required PluginType pluginType, dynamic data});
```

现成样例：`lib/plugins/trash/trash.dart`、`lib/plugins/blank/blank.dart`、`lib/plugins/ai_chat/chat.dart`。
「回收站」的打开方式（已验证可用）：
`getIt<TabsBloc>().add(TabsEvent.openPlugin(plugin: makePlugin(pluginType: PluginType.trash)))`。

### 落地步骤

1. `PluginType` 追加 6 个值（`localRecords / localCalendar / localCrm / localAi / localKbLinks / localWebDav`）；
2. 照 `lib/plugins/blank/` 的三件套（`XxxPlugin implements Plugin` + `XxxPluginWidgetBuilder extends PluginWidgetBuilder` + `XxxPluginBuilder implements PluginBuilder`）为 6 个模块各写一套，`buildWidget` 直接返回我们现有页面组件；
3. 在**我们自己的**注册点（`lib/extensions/extension_registry.dart`，启动时会跑）里 `registerPlugin(...)`，幂等；
4. 侧栏「本地模块」与窄条对应项改为 `TabsEvent.openPlugin(plugin: makePlugin(pluginType: ...))`；
5. 撤掉 `desktop_home_screen.dart` 里内容区自建的那层 Navigator（`localContentViewKey` 一并清理）。

### 风险（必须先扫，再改）

`PluginType` 是上游枚举，**追加值可能触发"switch 不穷尽"的编译错误**（上游多处按 pluginType 分支，
例如 layout/分析映射）。执行顺序必须是：先全仓扫 `switch` + `.pluginType` 的用法 → 逐处补分支 →
再加枚举 → 静态分析（失败自动回滚）→ 构建 → 截图验收。
