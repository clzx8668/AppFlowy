# 双平台信息架构决策（手机 / Windows）

> 结论先行：**数据与内核只有一套；界面外壳保留两套，但必须"同构"** ——
> 即两端用同一套信息架构（容器 → 记录 → 文档 → 模块页），只是呈现介质不同
> （手机＝抽屉＋底部五标签；桌面＝侧边栏＋多标签页）。
> 不建议"把手机外壳搬到桌面"，也不建议"两端各走各的"。

## 一、先厘清概念：现在到底有"几套"东西

| 层次 | 手机端 | Windows 端 | 是否同一套 |
| --- | --- | --- | --- |
| 数据与内核 | 内核 workspace / view / 文档 CRDT + 业务库 `business.db` | 同上（各自本机一份，靠 WebDAV 快照同步） | **同一套模型**（表结构、id 规则完全一致） |
| 容器与模块语义 | 读 `view.extra` 里的 `af_container / af_module / af_icon` | 同样读得到（就写在内核 view 上） | **同一套** |
| 业务模块页面 | 日历·日记 / CRM / AI 记忆 / 双链 / 快照同步 | 同一批页面组件（已公开复用） | **同一套组件** |
| 导航外壳 | `LocalHomeShell`：抽屉 + 底部五标签（首页/日历/CRM/AI/设置） | 上游侧边栏（工作区/收藏/页面树/回收站）+ 多标签页 | **两套呈现** |

所以现在的"两种模式"其实只是**两套外壳**，不是两套系统：
容器、记录、文档、业务表、模块页面全都是同一份。

## 二、为什么会有两套外壳（不是历史包袱，而是介质差异）

- 手机：屏幕窄，主流做法是"底部标签 + 抽屉"，一次看一个东西，返回栈是主交互。
- 桌面：屏幕宽、有键鼠，主流做法是"侧边栏文件树 + 多标签页 + 拖拽 + 快捷键 + 大纲"，
  可以同时开多个文档、批量操作。

两者服务的是**同样的信息**，但"打开方式/并行能力"天然不同。判断标准不是"哪个更高级"，
而是"哪个介质下效率最高"。

## 三、三条路线对比

| | A. 双外壳同构（推荐） | B. 全平台统一外壳 | C. 两端各走各的 |
| --- | --- | --- | --- |
| 做法 | 一套信息架构 + 两套呈现（手机抽屉五标签 / 桌面侧边栏多标签） | 桌面也套手机外壳（底部标签居中、单窗口单文档） | 桌面完全按上游走，我们的模块只在手机出现 |
| 体验 | 各自介质下最优 | 桌面丢掉多标签、拖拽、大纲、批量能力，宽屏大面积留白 | 两端功能不对齐，用户换端会"找不到东西" |
| 开发顺畅度 | 每加一个模块：写一次页面组件 + 两个入口，**逻辑只写一遍** | 逻辑只写一遍，但会一直和上游桌面能力打架（上游代码默认桌面是有侧边栏的） | 每加一个功能要写两遍，且容易语义漂移 |
| 内核/上游风险 | 低（只加轻量入口） | 中（要改上游桌面布局与路由） | 低 |
| 多端同步影响 | 无（同步的是数据，与外壳无关） | 无 | 无 |
| 结论 | ✅ 采用 | ❌ 不建议 | ❌ 不建议 |

**关于"多端同步"要澄清一点**：同步能不能顺畅，取决于**数据模型与 id 规则是否两端一致**，
与外壳长什么样无关。我们现在两端共用：内核 view id、`view.extra` 容器标记、
业务库表结构（`flash_notes / crm_customers / diary_entries / ai_digests / doc_links / webdav_config`）。
所以"同构"最大的价值不是同步，而是**同一套信息架构让两端功能对齐、开发只写一遍**。

## 四、目标形态：一张对齐表

| 信息单元 | 手机端 | Windows 端 |

| 知识库双链 | 文档底部反向链接面板 + 设置里的索引/图谱 | 同面板（桌面文档页同样生效）+「知识库双链」入口 ✔ |
| 快照同步 | 设置 → WebDAV 快照同步 | 侧边栏「本地模块 → 快照同步」✔ 已接 |

## 五、落地三步（后续开发按这个走）

1. **共享层固化**：模块页面一律写成平台无关组件（`CalendarView / CrmView / AiMemoryView /
   KnowledgeGraphPage / WebDavSettingsPage / KbLinksSettingsPage` 已是这个形态）；
   业务逻辑只放在扩展包 + App 适配器里，任何一端都不复制逻辑。
2. **桌面补齐三件事**：
   ① 本地模块入口（已完成，样式已对齐上游"搜索/新页面"行）；
   ② 侧边栏里的容器（闪念/笔记/CRM/AI）点进去要用**容器记录视图**（列表/网格/时间线），
      而不是普通文档页 —— 这是目前最明显的"两端不对齐"；
   ③ 桌面专属能力：多标签页已由上游提供，CRM 批量管理/表格视图后续挂在桌面。
3. **平台专属能力清单**（明确哪些"不需要两端都有"）：
   - 手机专属：抽屉手势、底部标签、FAB、随手记/悬浮入口、手势返回；
   - 桌面专属：多标签、批量选择、拖拽排序、快捷键、大纲面板、大屏 CRM 表格。
